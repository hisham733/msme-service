# D34 — Rubric snapshots + Filter History

## Rule

1. Every new filter verdict stores the **effective rubric** used:
   - 3 critical gates: label, threshold, instruction, criteria
   - 11 weighted criteria: weight, instruction, criteria
   - accept threshold, LLM assist, Jev model
2. `filter_results` stores `battery`, `config_hash`, `article_hash`, `article_text` and
   `article_len` beside the verdict.
3. `config_hash` is a short SHA-256 of the canonical rubric; changing a weight, threshold,
   wording or the accept threshold changes it.
4. **Re-run adds a new filter version to the same checklist row**. It does not create a new
   checklist row, receive run or archive folder.
5. `/filter-history.html` shows every version for one **email/checklist row** (not every email
   sharing a thread), numbered v1..vN for that row; it shows the exact rubric used, a config diff
   against the newest version, and a re-run action.
6. Existing rows without a snapshot stay legacy: they show “no rubric saved” and cannot be
   re-run until a new filter result exists.

## Verified

- Auto-filter row 391 saved a snapshot (`config_hash 8ebaed686025`, article 6,416 chars).
- Re-run created filter result **3** on the same checklist row **391**; history returns
  versions **3, 2, 1** (1 = legacy row 390).
- Full suite: **79 pass**.

## Rollback

The page and columns are additive. Restoring the old filter flow does not require deleting
the snapshots; they are ignored by the pipeline.
