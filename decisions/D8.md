# D8 — Vector logos in a PDF page header count as hasLogoInArticle

## Rule

The extract AI is text-only and cannot see any image. A logo/photo is counted only from deterministic
evidence:

1. **Raster** images in a PDF (`/Subtype /Image`) or DOCX (`word/media`, header-aware) — unchanged.
2. **Vector** artwork in a PDF `/Artifact … /Subtype /Header`: a shape with ≥20 path ops and a non-white
   fill, or a painted non-full-page block (20–400 pt, top 30%) with colour/vector detail → a logo.
3. When `classify_doc_images` finds a logo/photo **inside the article document**, `pipeline` sets
   `hasLogoInArticle` / `hasImageInArticle` true even if the text-only AI said false.

A text-only wordmark (letters, no vector shape) is not detected — parked as `T-016` note.

## Why — measured

Email `1a10974d2a0cbab5` (ACCA op-ed) attached a 4-page PDF. `page.images` = **0 on every page**; the ACCA
logo is vector: red fill `0.929 0.11 0.141 rg`, a 55.9×55.9 block, **155 path ops** inside
`/Artifact … /Subtype /Header` on all 4 pages. The checklist said `hasLogoInArticle=false`. Across the
85 archived PDFs the new rule flags only this file (no false positives on full-bleed backgrounds/clips).

**Rollback.** Remove `_pdf_header_vector_logo` and the pipeline override; the old raster-only behaviour
returns.
