# D2 — FILE HEADER contract on every website-runtime .py

## Rule

Each of the 26 website-runtime modules starts with a `FILE HEADER` block carrying: `file` · `role`
(stage + port) · `owner` (Hisham, human owner; AI sessions amend under his review) · `purpose` ·
`pages` (page routes, or n/a) · `calls` · `called` · `amend` (what may change, what must not break,
proving command). The original module docstring stays below it. No dates or change-log in the header —
they go stale; git and the reply carry history.

## Why — measured

The existing docstrings state what a module does and give examples, but none says who may change it,
which port/page it backs, or which callers break. `filter_service.py` alone serves 12 page routes and
imports only `filter.py`; `dashboard.py` and `main.py` duplicate route names — an editor needs the
boundary in the file itself.

**Rollback.** Remove the header block; the docstring below is untouched and still valid.
