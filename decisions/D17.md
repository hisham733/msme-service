# D17 — Google-native export support

## Rule

`drive_fetch.fetch_file` now exports Google-native files instead of rejecting them:

- **Docs** → `text/plain`;
- **Slides / Sheets** → `application/pdf` (text extracted + embedded images classified);
- **Drawings** → `image/png` (media asset);
- other Google-native types → still `unsupported_google_file`.

Exports are capped by `DRIVE_MAX_FILE_BYTES`; the exported PDF/PNG is archived as the original/media.

## Why — measured

MATRADE SEMICON WEST `1a15c5a14ead29e2`: the Drive link is a Google-native file (not PDF/Doc) — the old code
returned `unsupported_google_file`, the body was only a cover pitch, so `hasArticle=false`/`needs_human`.
Unit test with a fake Drive service: Slides/Sheets export → PDF (9,036 chars text + image classification),
Drawing → PNG, Doc → text; all `ok=true`.
Live re-run is blocked by the expired OAuth token (`T-028`).

**Rollback.** Restore the `unsupported_google_file` branch.
