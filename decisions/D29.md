# D29 — SQLite-only checklist storage

## Rule

1. **`checklist.save_checklist()` writes to SQLite only** (`data/msme.sqlite3`); the receive
   pipeline no longer appends to Google Sheets.
2. **The dashboard reads SQLite**, so it is unaffected by Sheet availability or permissions.
3. **The Sheet is optional.** `CHECKLIST_SHEET_ID` and `CHECKLIST_TAB` remain in Config for a
   manual/export reference, but receive does not sync to them. The existing Sheet is left as-is.
4. **`POST /api/clear` clears SQLite only**; it no longer clears the Sheet.
5. **Published links stay in Google Drive** (T-044 closed 2026-10-26). The checklist
   `folderId` / `folderUrl` remain empty and the dashboard “open” column stays blank by design.

## Why

- The Sheet returned **403** earlier and was empty (header only) while SQLite held **210 rows**.
- `save_checklist()` already treated a Sheet failure as non-fatal, so the Sheet never drove the
  dashboard or filter.
- Removing the append removes a network call and a second source of truth from every run.

## Rollback

Re-add a Sheet append call with the configured `CHECKLIST_SHEET_ID` / `CHECKLIST_TAB`; no data
migration is needed. The Sheet header (14 columns) is unchanged.
