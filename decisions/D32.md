# D32 — One receive+filter pipeline, one port

## Rule

1. **One external port: `:8899`.** `combined.py` dispatches to `dashboard.app` for receive paths
   and `filter_service.app` for filter paths. `run.py` starts one uvicorn worker.
2. **Filter runs inside the receive pipeline** when `readyToFilter=true` and
   `ENABLE_AUTO_FILTER=true`. `filter.judge()` is called in-process; no :8900 HTTP dependency.
3. **Filter results are separate but linked.** `filter_results.checklist_id` points at the
   checklist row; `db.list_checklist()` returns the latest result (`filterStatus`,
   `filterOutcome`, `filterWeighted`, `filterGate`, `filterVerdict`).
4. **A filter error never fails receive.** The row is saved with `filterStatus=error`; the
   filter stage shows the error. `ENABLE_AUTO_FILTER=false` skips auto-filter.
5. **Archive policy: keep all.** Every ready article is archived regardless of filter outcome.
6. **One config page** at `/config.html` combines receive settings with an embedded filter
   rule editor (`/filter-config.html`). Lab/Test/Report pages stay available on :8899.
7. **Audit trail remains** in `data/filter_verdicts.jsonl` (`source=receive`) for the existing
   verdict/log/report pages.

## Why

The old split (:8898 receive API, :8899 dashboard, :8900 filter) made one email a two-step
manual workflow. The user asked for one place, one pipeline and one config.

## Live proof

- One port exposes only `8899:8899`; `/health`, `/checklist.html`, `/filter.html`,
  `/filter-config.html`, `/config.html` all return 200.
- Ready email `1a175ac2c4797d1c` auto-filtered in the same run:
  checklist row **390**, `filter_results` linked, outcome **ACCEPT**, weighted **90**,
  model `jev-1.14.0`; archive done; JSONL entry `source=receive`.
- Full test suite: **69 pass**.

## Rollback

- `ENABLE_AUTO_FILTER=false` returns to receive-only without a rebuild.
- The old split services remain importable (`main.py`, `filter_service.py`) but are not started
  by `run.py`.
