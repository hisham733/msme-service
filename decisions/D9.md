# D9 — Body/downloaded logos count as `hasLogo`, not `hasPic`

## Rule

`hasLogo` means a standalone logo asset was provided **anywhere**: an attachment filename containing
"logo", an inline HTML-body image classified as a logo (max dim ≥ 200 px), or a direct asset link that
returns an image. It is **never** counted as `hasPic`; `hasPic` stays for real photos only.

A direct asset link is fetched only when it returns `image/*` (cap 15 MB, max 2 links); an HTML page is
not parsed (`T-013`). Classification uses the **filename/URL first** ("…Logo.png" → logo), then
dimensions — so a 1220×1281 logo is not mistaken for a photo. The full-resolution asset replaces the
inline thumbnail in `images/`.

## Why — measured

Email `1a10ec703a3c6578` (Aventra) has no attachment and no photo: 2 inline vertical-logo thumbnails
(264×277, 270×284), 3 social icons (64×64), and a `media-outreach.com/i/Download/…` link returning a
**1220×1281 PNG** named "Aventra Group Vertical Logo.png". D7 kept only photos, so every flag was false
and `readyToFilter=false` despite a usable logo being present.

**Rollback.** Remove the body/asset logo buckets; logos stop counting again.
