# D44 — N-2 "library update" intake

## Rule

An email whose purpose is to send a **new logo or building photo** (no article) is a **gallery
update**, not "no article".

1. **Detection (decision 1 = B)** runs after extract and before verify; a hit needs **all three**:
   1. no article text — `body_text < 400` chars and no ranked candidate ≥ 400 chars;
   2. ≥ 2 positive signals — (a) phrase in subject/body ("new logo"/"building photograph"/…),
      (b) attachments are images only (no DOCX/PDF), (c) decide `chosenFileName=""` + `imagesAvailable=true`;
   3. zero negative signals — "for immediate release"/"press release"/"media release"/"siaran akhbar",
      or report/contribute/byline markers.
   A `needs_human` with no collected asset stays on the normal path.
2. **Storage:** `data/gallery/updates/<date>_<brand-or-subject>/update.json` + `images/` + `originals/`;
   nothing written to `all_emails/`. Each file records `name`, `sha1`, `bytes`, `width`, `height`, `kind`.
3. **Promotion (decision 2 = C):** a captured logo is **auto-active** only when all four hold —
   the file is a logo (≥ `BODY_LOGO_MIN_DIM` or vector, name not building/facade), brand confidence
   high (sender-domain match, or exact subject alias + corroboration), the brand already has an active
   logo, and the file is readable within `GALLERY_MAX_FILE_BYTES`. Otherwise **pending** with
   `promotionBlockedReason` (`new-brand` / `not-a-logo` / `low-brand-confidence` / `unreadable`).
   Human path: `tools/gallery_admin.py promote <id>` / `discard <id>`.
4. **Row / reply / UI (decision 3 = A):** a `emailType` column (default `press_release`) outside the
   14-column CSV contract; a hit sets `emailType=library_update`, `hasArticle=false`,
   `readyToFilter=false`, `articleFile=""`, skips verify/filter/reply, and the checklist/editor show a
   "Library update" badge instead of "no article".

## Why

The 30-Oct call's BPMB logo + building-photo email was factually "no article"; the fix is the
*classification*, not the email. The receive pipeline currently marks such emails `needs_human` and
sends the "send us the article" reply. N-2 routes them into the gallery store (feeding N-1), never
publishes from a pending entry (N-1 matches only `active`), and stops the wrong reply.

## Rollback

Set `GALLERY_ENABLED=false` is unrelated; N-2 has no separate switch but is safe — a miss continues
the normal path, and a false hit only stores assets it can never auto-publish (pending unless the
brand is already active and the file is a real logo). Revert by deleting `emailType` from the
checklist migration and removing the `library_update` stage branch in `pipeline.py`.
