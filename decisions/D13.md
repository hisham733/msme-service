# D13 — A linked Drive image is media, not the article

## Rule

When the Drive **file** link resolves to an image (`mimeType image/*` or an image extension), the run keeps
the article text from the email/attachment and treats the file as a **media asset**:

- photo dimensions → `hasPic`; logo (name/dimensions) → `hasLogo`;
- saved into `images/` with the article;
- **never** `needs_human` — an image cannot be "text extraction failed".

A non-image Drive file with no extractable text (scanned PDF) still ends `needs_human`.

## Why — measured

redBus `1a132a1205a3a762`: the Drive link returned `redBus - Krishnan.jpg`, `image/jpeg`, 8,749,100 bytes.
`fetch_file` extracted 0 text chars, so the old branch marked the run `needs_human` and discarded the
article already present in the email body. After the fix: `hasArticle=true`, `hasPic=true`, subject 95,
`readyToFilter=true`; the image is archived.

**Rollback.** Restore the text-only Drive-file branch; linked images become needs-human again.
