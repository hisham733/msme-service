# D23 — Google Docs link support

## Rule

`drive_fetch.doc_id_from_link()` recognises `docs.google.com/document/d/<id>` (including `/u/0/` forms). The
pipeline maps it to the Drive file id and uses the existing Google-Doc export (text). A `google_doc_fetch`
stage records the doc id, name and text length. The media gate is unchanged: a Doc with no images does not
make the row ready.

## Why — measured

Contributed Article `1a0fbe5251974652`: the draft is a Google Doc owned by `surabhi@syncpr.co`; the pipeline
only recognised `drive.google.com` links, so it treated the email as a pitch. The Doc exports **7,302 chars**
and the title matches; its PDF export has **zero images**. After the fix: `hasArticle=true`, subject 100,
`hasPic/hasLogo=false` → still not ready (no Atlas Copco photo/logo). The SYNC signature logo (96×25 GIF) is
the agency’s, not the client’s, and is not counted.

**Rollback.** Remove the Doc branch; the draft link is ignored again.
