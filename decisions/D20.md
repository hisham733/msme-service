# D20 — Public web article fallback

## Rule

When there is no attachment / Drive / OneDrive / Box article and the email body is a **cover note**
(clean body < ~2,500 chars with no release/dateline marker), the pipeline fetches one article-like public
HTML URL from `linkToFetch`/`linksFound`. It extracts the title and paragraph text (no nav), and media:
JSON-LD publisher logo / `og:image` / content images. A `logo|share-logo|default-meta-image` asset counts as
**hasLogo**; a content photo counts as **hasPic**. HTML only; caps 5 MB/20 s; social/tracker/Drive links
skipped; failures are recorded and never block the run.

This is a fallback: body-only releases (IRGCE) and attachment/kit articles (ACCA/EAP) are not overridden.

## Why — measured

World Bank speech `1a14715b2456c82b`: the email only links the worldbank.org page. Page 200, title matches,
13.6k chars of speech text, **no news photos**; `og:image` default is 404 but the JSON-LD publisher logo
`share-logo/social-share.jpg` (780×439) is valid. Live run `16a1ed34-…`: `hasArticle=true`, `hasLogo=true`,
subject 100, `readyToFilter=true`; the speech text + logo are archived.

**Rollback.** Remove the `web_fetch` branch; the speech returns to not-ready.
