# D15 — Public OneDrive share support

## Rule

The receive resolves `1drv.ms` / `onedrive.live.com` share links with a browser User-Agent and a cookie
jar (the page issues a guest `FedAuth` cookie), then lists children with the v2.0 item API:

```
GET https://onedrive.live.com/personal/<cid>/_api/v2.0/drive/items/<item>/children?e=<e>
```

Files download via `@content.downloadUrl` (or `/content`). The kit is fed into the existing pipeline as a
Drive-shaped media kit (release picker D12, image rules D7/D9/D11, archive). A single-file share is handled
by falling back to the item metadata when `/children` returns 404.

**Never** use the old `api.onedrive.com/shares` endpoint (401) or a bot User-Agent (403).

## Why — measured

APAC `1a15cd202b2900a9`: short link → guest `FedAuth`; children returned
`Egon Zehnder APAC_PressRelease_CEO Report 2026.pdf` (488,391 B) and `The CEO Response 2026_Egon Zehnder.pdf`
(1,161,389 B); both downloaded with a Chrome UA and text extracted. Live re-run `dc2e65ac-…` → OneDrive
stage `done`, 2 docs, article ready; the press-release PDF supplies the logo/photo evidence.

**Rollback.** Remove the `onedrive_fetch` branch; the link is ignored again.
