# D18 — Folder behind a /file/d/ link

## Rule

A Drive link of the form `/file/d/<id>` may return metadata `mimeType =
application/vnd.google-apps.folder`. In that case the pipeline calls `fetch_media_kit(<id>)` and treats the
folder exactly like a `/folders/` link: pick the release (D12/D16), download images/docs, archive, and
classify. The release picker also penalises names containing `report`/`summary` so a short "Press Release
Report" does not beat the full release.

## Why — measured

MATRADE `1a15c5a14ead29e2`: the `/file/d/…` link is a **folder** containing
`[PRESS RELEASE] MATRADE-LED …docx` (5,155 chars) + `Press Release Report.docx` (1,783) + 3 photos + logo.
The old file branch returned `unsupported_google_file` → `needs_human`. After the fix the picker selects the
full release; live run `c09bbb5c-…` → `hasArticle=true`, `hasPic=true`, `hasLogo=true`, subject 96,
`readyToFilter=true`; archive has the 4 images + originals.

**Rollback.** Restore the file-only branch; folder links become needs_human again.
