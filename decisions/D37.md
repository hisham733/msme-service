# D37 — Local login and versioned filter configuration

## Rule

1. **Local accounts only** (no Google login). `combined.py` wraps the app in
   `auth.AuthGate`; every request is checked once, before dispatch.
2. **Two roles.** `admin` reaches everything. `editor` reaches only `/editor.html`,
   `/api/editor/*`, the filter-config pages/endpoints (`/filter-config.html`,
   `/config.json`, `/filters.json`, `/config-versions` read) and their draft images under
   `/repurpose-site/`. Everything else is 403.
3. **Sessions last 7 days**: an opaque token in an `HttpOnly`, `Secure`, `SameSite=Lax`
   cookie; only a SHA-256 hash is stored. A CSRF token (readable cookie + `X-CSRF-Token`)
   is required on every non-GET except login and the Gmail webhook.
4. **Passwords** use stdlib scrypt (per-user salt), minimum 12 characters, constant-time
   verify; 5 failures in 15 minutes lock that username/IP pair. Unknown usernames still pay
   a dummy hash (no enumeration).
5. **First admin** comes from `AUTH_BOOTSTRAP_USERNAME` / `AUTH_BOOTSTRAP_PASSWORD` only
   while the users table is empty. After the first sign-in the password is changed and both
   variables are removed from `.env`.
6. **Users are never deleted**, only disabled; at least one active admin must remain. Admin
   reset forces a password change at next sign-in and revokes that user's sessions.
7. **Every filter-config save is versioned** — `/config.json` PUT and the testfilter
   promote/sync/rollback actions record actor, time, full battery snapshot and config hash.
   Restore is admin-only and writes a **new** version with `restored_from`; history is never
   rewritten. `/config.json` accepts only `ENABLE_LLM_ASSIST` and `ACCEPT_THRESHOLD` as
   settings, never receive or AI-key settings.
8. **The webhook stays public**; its auth is the Pub/Sub OIDC token, not a session.
   `/health`, `/login`, `/api/auth/login` and `/auth.js` are the only other public paths.
9. Cloudflare Access is not required; the application login is the boundary.

## Why

The dashboard and both config editors were reachable without a login, on the same public
tunnel as the webhook. An editor needs to change the rubric without seeing or changing the
receive keys, the Gmail query or the operations pages. Changes to the rubric must be
attributable and reversible.

## Evidence

- **138 tests pass** (`python3 -m unittest discover -s tools -p 'test_*.py'`), including 33
  new auth tests: hash roundtrip, session expiry, 7-day cookie flags, admin/editor matrix,
  302/401/403 gate decisions, CSRF, rate limit, last-admin protection, version/restore and
  audit sanitization.
- Live through `https://hook.empi.site`: anonymous `/` → 302 `/login`; anonymous
  `/api/run` → 401; `/webhooks/gmail` → 401 (OIDC, not a redirect); admin login 200;
  `/`, `/users.html`, `/filter-config.html`, `/config.json`, `/config-versions`,
  `/api/users`, `/api/audit` → 200; logout without CSRF → 403, with CSRF → 200.
- Webhook regression after the gate: a real Pub/Sub push returned **200**, event `done`,
  history replayed (0 ids, cursor advanced by the test) — the gate did not break it.
