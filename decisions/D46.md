# D46 — Partner handoff P0-1 / P0-2 / backfill

## Rule

**P0-1 — article-keyed, not folder-keyed.** The canonical article key is **`checklist.id`** (no parallel
UUID). Folder names can change, so the dashboard joins on `article_id`:

- `checklist.article_hash` — duplicate detection (backfilled from the latest `filter_results.article_hash`).
- `stage_runs` — one row per stage execution (`run_id` PK, `article_id`, stage/service/status/timestamps/error).
- `article_events` — the append-only dashboard event log (`article_id`, stage, status, reason, actor, payload).
- `validation_results` — per-rule validator results (`article_id`, `run_id`, rule, level, ok, detail).
- `images` — image-selection provenance (`article_id`, path, role, rung, selected, reason).
- `repurpose_runs.article_id` and `repurpose_events.article_id` — added and backfilled from `checklist_id`.
- `_connect()` sets `PRAGMA busy_timeout = 5000`.
- Acceptance: `db.article_timeline(article_id)` returns receive → filter → repurpose → validation (+ events)
  in one call.

**Backfill.** `tools/backfill_repurpose.py` rebuilds the DB mirror from `data/repurpose_export.json` +
each `repurpose_inbox/<folder>/run.json` (exports, runs, events, validation, images), with
`article_id = checklist.id`. Dry-run by default; `--apply` writes; idempotent (derived rows replaced,
one backfill event/folder).

**P0-2 — agent git policy.** `opencode.json`: `git commit*: allow`, `git push*: ask`, `git pull*: ask`
(an agent never force-pushes and never commits `creds/`, `data/`, `all_emails/`, `.env`). Recorded in
`COLLABORATION.md`.

## Why

The old DB was folder-keyed; a dashboard cannot reliably join across receive/filter/repurpose when a
folder name changes. `checklist.id` already exists, so it is the single key. The migrations are code
(`init_db` + `ALTER TABLE`) with tests, per the collaboration's "schema = code" rule; the DB file stays
data. The backfill closes the empty `repurpose_exports/runs/events` on a fresh install from the folder
contract.

## Rollback

Additive only: drop the four new tables and the `article_id`/`article_hash` columns; the pipeline and
engine ignore them. The backfill only writes derived mirror rows; the folder contract (`run.json`) is
untouched.
