# D-015 — Shared defaults vs machine overrides

## Rule

`config.json` is committed and holds **shared** settings: model id, base URL, retry limit, intake rules.
`config.local.json` is **gitignored** and holds this machine's overrides: the two roots, a local model or
port. The dashboard's Settings page writes only the local file. Effective config = shared, with local
merged one level deep on top (lists replaced, not concatenated).

## Why — measured

Before this, Settings wrote `config.json` directly. Every path edit on either laptop therefore made the
tracked file dirty, and a pull carrying the other person's path produced a conflict in a file neither
person meant to change. The handoff contract also told the partner to edit the committed file, which
guaranteed the same conflict on their machine. The local layer removes the conflict by construction: a
path is a fact about one laptop, not about the project.

**Rollback.** Delete `config.local.json`, restore `_apply_settings` writing `config.json`. One file.
