# D-016 — Do not guess the receive stage's folder shape; measure it

## Rule

1. The repurpose stage consumes **one folder per article**: `<release text>.md`, optional `link.md`,
   `images\`/`originals\`.
2. The names are configurable under `intake` (`release_text_glob`, `release_text_exclude`, `link_names`,
   `image_dirs`, `extra_image_dirs`, `require_link`) — never hard-coded per partner.
3. `python -m pipeline.preflight` is read-only and reports, per folder, PASS/WARN/FAIL with the reason.
   Its exit code is 1 on any FAIL, and it fails a folder with **two** release texts rather than silently
   reading the first.
4. A flat root (release texts loose, not in folders) is a FAIL, because it cannot represent one article
   per folder.

## Why — measured

`scan.find_release_text()` used to return the first `.md` it found. On a folder holding two releases,
that is a silent wrong article — the most expensive failure mode here, because the run looks successful.
The demo fixtures `demo_releases_bad/` encode both failures and the tests assert preflight refuses them.
The synthetic `demo_releases/` PASS with zero warnings, which is what lets the partner prove the seam
without a client e-mail.

**Rollback.** Remove the `intake` block; defaults reproduce the old behaviour except preflight's FAIL on
ambiguity, which should not be rolled back.
