# D-013 — the image-sourcing policy belongs to MSME, not to our README

## What was wrong

The README carried this as **hard rule 5**:

> *"No AI-generated images in an article by the Sept-2026 editorial guideline (use supplied assets);
> ⚠ open conflict — the boss asked for self-generated images, see `meeting_notes/` (T-004)."*

That mixed three different things in one line: a client instruction (the `.docx`), a client verbal
request (the boss), and **our** operating choice. A hard rule asserts a settled decision — and this one
is not settled. MG's correction: it should be a decision, and it has been removed from the README.

## The decision (as it stands)

**No decision has been made by MSME yet.** Until it is, EF operates on the conservative reading —
supplied material, the release's media kit, or the publisher's library; never a generated image — because
that is (a) what the client's own written guideline says and (b) the safer position for a client
publication. The engine enforces it (`imgselect` never generates) and will keep doing so until this row
changes.

The three options on the table for MSME (30 Oct):

| option | meaning | effect on the pipeline |
|---|---|---|
| **a** | supplied material only — the guideline stands | today's behaviour; `IMAGES_MISSING` → `image-error` when nothing is supplied |
| **b** | generated images permitted under stated conditions (labelling? only when nothing is supplied? which model?) | a new produce step + a labelling/watermark rule + a provenance field in `run.json` |
| **c** | an editor decides per article | a dashboard control + a mandatory reason on the record |

## Consequences

- The README no longer asserts a policy; it points here. **Do not re-add it as a hard rule** before
  MSME answers.
- `T-004` is the open question; this decision is its home until it is answered, at which point this file
  is superseded rather than edited.
- The 30 October meeting brief carries it as **Decision 7** with the three options spelled out.
