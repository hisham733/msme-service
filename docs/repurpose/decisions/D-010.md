# D-010 — the image decision is code, not the model's prose

**Status:** decided · **Date:** 2026-10-23 · **Owner:** EF session S07 #5 · **Area:** images, engine

## Context

Until today the draft's `## Images` section came out of the same LLM call that wrote the article. The
model never saw the pictures, so it worked from filenames, and it produced the failures recorded in
`msme-image-select/CHANGELOG.md`: the people rung claimed for `1.jpg`, a featured file that was not on
disk (`FEATURED_EXISTS`), captions that named nobody in particular.

## Decision

**The image decision is produced by `pipeline/imgselect.py` and injected into the draft; the prose model
no longer chooses images.** `pipeline/llm_step.py::draft_release` replaces whatever `## Images` block the
model wrote with the code's block (`replace_images_section`), and `run.json` records the decision
(`image_rung`, `image_file`, `image_declared`). The model keeps the prose; the skill owns the pictures.

The decision itself is three layers: deterministic gathering/cleaning (`harvest.py` + dedupe), a vision
pass over the pixels (`vision.py`), and a story-gated ladder plus naming (`imgselect.py`). Language
judgement (who issued the release, what kind of story it is) is delegated to one LLM context call per
folder — cached, so it is free on re-run.

## Why

- **Measurable.** A code decision can be scored against TARGET on 30 published pairs: rung **90%**,
  asset **83.3%**, rename **100%**, in-body **100%**, exact match **80%**
  (`pipeline/IMAGE_GUIDE.md` §4). A prose decision cannot be scored at all.
- **Deterministic and auditable.** The same folder gives the same answer, and `run.json` records it.
- **It caught a receive-stage defect**: 10 of the 17 published images that looked "missing" were inside
  the supplied `.pdf`/`.docx` all along (§1.2 of
  `session_analysis/2026-10-23_S07_engine-use-guide/5_image-select-training-reply.md`).

## Consequences

The eye is specified in `pipeline/VISION_MODEL.md`; the same folder gives the same answer, and
`run.json` records it.

- Skill edits now mean **code edits**, logged in the skill's three files **and** in
  `pipeline/IMAGE_GUIDE.md`; the engine's dev suite flags drafts made by an older version.
- The `msme-image-select/SKILL.md` remains the human/LLM-readable specification of the same rules, so a
  session without tools can still do the job by hand.
- Cost per folder: 1 vision call + 1 context call + 1 caption call per used image, all cached.
