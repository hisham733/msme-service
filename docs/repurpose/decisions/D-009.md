# D-009 — the website lives under DLW; the release folder keeps the record

## Rule

- The rendered article page is `DLW\articles\<slug>.html`; the images it shows are copied to
  `DLW\images\<renamed>` (the image skill's `<Subject>_<Month>_<Year>_MALAYSIA-SME.ext` names).
- The release folder keeps the **record**: `draft.md`, `draft.prev.md`, `run.json`, `images\`,
  `originals\` — and no longer holds the website (its `site\` folder is cleared by the builder).
- `config.json` stays the single edit point; index URLs are relative and percent-encoded.

## Why — measured

Windows browsers refuse file paths over ~260 characters. Measured 2026-10-23: the BMW article built
under `Email_Articles\<release>\site\` had a **272-char** path and Edge returned
`ERR_FILE_NOT_FOUND` although the file existed; the same page under `DLW\articles\` is **158 chars**
and loads (headless Edge DOM check). The release folder names come from MSME's email subjects and are
long and not ours to rename. The co-location idea (2026-10-22 §2 = A) survives where it matters — the
article's drafts and manifest stay with the release — but the *website* cannot live on that path.

## Rollback

Point `build_site.build_all` back at `<release>\site\` (one block) — the page will break again for
release folders whose full path exceeds 260 characters.
