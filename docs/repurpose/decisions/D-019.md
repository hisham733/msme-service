# D-019 — The measured operating point is 62; the parameter belongs to the Filter engine

## Rule

1. On the 2026-10 reports, the operating point that was measured and agreed is **WAS ≥ 62** with critical
   gates ≥ 90. It reproduces the round-1 agreement and reduces false accepts.
2. **It is not an exported constant.** The gate weights, the cut and where they are stored are
   **tunables of the Filter engine**, which the partner owns. This repository measures a given cut; it
   does not prescribe or store the partner's setting (D-023).
3. `filter_stage.py` keeps `CUT = 62` only as the **default used to reproduce the D-019 measurement**;
   `report --cut N` measures any other value. `PUBLISHED_CUT = 60` keeps the 2026-10 reports reproducible.

## Why — measured

On the 145 scoreable rows, at cut 62: agreement **123/145 = 84.83 %** (unchanged), false accepts
**13 → 9**, false rejects **9 → 13**, self-flip **3/19 → 1/19**. MG chose 62 for that trade. Putting the
number in a shared config or an exported pipeline would be the wrong place: the partner's engine may
store its tunables elsewhere, and a fixed value in our artifact would look authoritative after the next
batch moves it. The measurement is a fact; the setting is the Filter owner's.

**Rollback.** `report --cut 60`; no config change is needed because none was written.
