# D-003 — Logo/banner fallback for the featured image

## Rule

When the receive stage supplies **no usable image** but a **logo or banner related to the article**
exists, the image skill uses it as the featured image (source order: release media kit → supplied logo
assets → MSME media library). HOLD only when **no related visual exists at all**. The docx's
"people first, then brand logo" ladder otherwise stands; unrelated decorative art is never a fallback.

## Why — measured

MIHAS-type and statement articles depend on this path: in the 30-pair corpus, **12 of the 14**
featured images not present in the receive folder are logos or event visuals pulled from outside
(11 logo + 1 event banner, including library uploads dated months earlier). Published practice since
March-2026 confirms it (S02 §5: MIHAS, ACCCIM, SC). Without this rule the image skill either HOLDs
those articles or has no defined fetch target.

**Rollback.** One line: restore docx strictness (HOLD when no supplied visual).
