# D-022 — Commit/push authority is delegated, not withheld

## Rule

1. A session **may** run `git commit` and `git push` **when MG asks for it or approves it in the
   conversation**. The approval is the decision; the keystroke is the session's.
2. Absent a request or approval, a session leaves the tree clean and reports what is staged/unstaged; it
   does not push on its own initiative.
3. A push follows the model in D-020: topic branch → PR, or — when MG asks for a direct main push — the
   main push is allowed and CI still runs. Never force-push history that someone else may have pulled;
   the one rewrite before the first push (D-021) was performed with MG's authorisation.
4. Destructive operations (`reset --hard`, history rewrite, tag force-update) still need an explicit
   request, not a general push approval.

## Why

The old rule ("commits are local; pushes are MG's") was written when no agent had repository access. It
made every handoff a manual step and left 238 files uncommitted for two days. The risk the rule managed —
an agent pushing unreviewed work — is now managed by CI + the three-file skill gate + the PR model. The
remaining risk is a destructive command, which rule 4 keeps gated.

**Rollback.** Delete this decision and restore the "pushes are MG's" line; nothing in code depends on it.
