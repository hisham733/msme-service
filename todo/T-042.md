## T-042 Unread-only refresh

`gmail.list_unread()` trusts the query it receives; the configured query is
`in:inbox -category:promotions` (no `is:unread`) in `config.py`, `settings_store.py` and
`data/settings.json`. So `/api/emails?force=1` returns **read + unread** inbox mail, and
`/run-all` / the scheduler can re-process read messages.

✅ **DONE 2026-10-24**

- `gmail.list_unread(..., unread_only=True)` appends `is:unread` when missing; the reply
  thread lookup (`dashboard.py:436`) passes `unread_only=False`.
- `config.py`, `settings_store.py`, `data/settings.json` and `docker-compose.yml` now use
  `in:inbox is:unread -category:promotions`.
- A **single successful run** now marks the email read in `dashboard._process_one` and
  `main._process_one` (both success and `needs_human`); `/run-all` and the scheduler already
  did. The duplicate `mark_read` in the run-all endpoints was removed.
- The checklist page force-refreshes the picker after **success** and **needs_human**, and the
  `needs_human` status now stops polling instead of looping.

**Tests:** `python3 -m unittest tests.test_gmail_unread -v` → **8 pass**; full tools suite
**52 pass**.

**Live:** `GET /api/emails?force=1` returned **2** emails, both with the Gmail `UNREAD` label;
`data/emails_cache.json` now has **2** entries (was 50 with read mail). No checklist/archive/DB
write. The next real single run will mark its email read.

**Evidence:** `gmail.py`, `dashboard.py`, `main.py`, `static/checklist.html`,
`tests/test_gmail_unread.py`.
