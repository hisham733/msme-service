## ✅ T-043 Published-release media

✅ **DONE 2026-10-26** — replaced the PitchMyStory-only fix with a generic probe (D28).

- `web_fetch.py`: 3-state `candidate_links`, content probe (`is_article`), SSRF guard,
  publisher-logo separation, WebP `.webp`; DNS/fetch retries for the Docker resolver.
- `pipeline.py`: reads `WEB_FETCH_MODE`; `off` skips `web_fetch`/`body_images`/`asset_link`;
  only `ok and is_article` text/media enters the candidate pool; publisher logos never
  set `hasLogo`.
- `extract.py`: WebP dimensions (VP8/VP8L/VP8X). `normalize.py`: `linkTexts`.
- Config page + API: `WEB_FETCH_MODE` select, `WEB_KNOWN_SITES` textarea; invalid mode
  becomes `probe`, empty known list is allowed.
- Live Event Me Now dry-run: `probe` → `hasPic=true`, `hasLogo=false`,
  `readyToFilter=true` (subject 100; 151,524-byte WebP); `known` → true; `off` → false.
- Tests: `tests/test_web_probe.py` 7 pass; full suite **62 pass**.
- Settings restored to `probe`.

The original diagnosis follows.

The Event Me Now email (`1a1160f03ca04ae4`) links to
`https://www.pitchmystory.com/newswire/malaysia-s-event-industry-gets-a-new-digital-home-with-event-me-now`.
The page returns **200**, has the full release, and a **1536×1024 WebP featured image**
(OG image, 151 KB).

Receive ignores it because:

- `web_fetch.is_article_url()` rejects `pitchmystory.com/newswire/…`;
- `extract._image_dims()` cannot read **WebP** (returns 0×0);
- the only images it sees are PitchMyStory’s own brand logos, which would count as
  `hasLogo` (wrong media).

**Fix planned:** add PitchMyStory to the article allowlist; parse WebP dimensions; use the
OG/featured image as `hasPic`; ignore the distributor’s brand logos. Re-run the email and
expect `readyToFilter=true` (article + photo + subject 100).

**Done when.** The Event Me Now dry-run returns `hasPic=true` / `readyToFilter=true` with
the featured image, and a unit test covers the PitchMyStory URL + WebP dimensions.
